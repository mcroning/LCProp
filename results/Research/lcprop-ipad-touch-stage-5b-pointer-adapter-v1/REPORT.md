## Event translation

Primary touch and pen tip contacts map to synthetic mousedown/mousemove/mouseup with left-button semantics. Pencil pressure/physical tilt/hover are ignored; Action: Tilt retains its optical endpoint meaning. Synthetic events have isTrusted=false, so browser/ipympl acceptance is a hosted qualification gate.

Coordinates remain CSS clientX/clientY. The existing ipympl mouse handler applies bounding-box conversion, device-pixel ratio and Matplotlib's y-axis conversion; the adapter must not apply these twice. Local mocks verify coordinate preservation, while controller tests verify data-coordinate changes independently. The full browser-to-Python conversion, browser zoom and Retina scaling remain untested.

Pointer capture is requested at gesture start; failure sends no press. pointercancel, lostpointercapture, pointerleave, outside-canvas coordinates, contact loss, additional contact in the same document, blur, hidden document and manual removal send mouseleave, **not mouseup**. Existing BeamPlane figure_leave cancels provisional geometry. Successful release sends one mouseup. A short 100-ms restart guard limits rapid contact reuse; this deliberately ignores faster touch gestures and is not a production usability policy.

The notebook sets public pan_zoom_throttle=0 before creating the displayed view, avoiding the normal 33-ms trailing throttle window. Lodash scheduling and comm order still require actual frontend traces. Cancellation, rerender and stale-event safety must be checked end-to-end, especially because legacy mouse messages carry no gesture generation ID. No claim of proof against every stale-event race is made.

Synthetic MouseEvents are tracked in a WeakSet. Capture-phase guards suppress other mouse events during touch and for 800 ms afterward, plus events marked as touch-generated by sourceCapabilities. A genuine mouse pointerdown retains the desktop path and clears suppression. This is a bounded experimental heuristic: cross-input timing and browsers that report compatibility input differently must be tested. It is not a proven universal deduplication mechanism. The adapter never suppresses events globally; only its selected canvas has touchAction=none. Outside notebook scrolling must be confirmed on iPad.

## Supported API use and private assumptions

Standard PointerEvent, MouseEvent dispatch, pointer capture, scoped style assignment, add/removeEventListener and DOMWidget.add_class are used. Colab output.eval_js evaluates JavaScript in the current cell context, per [Colab's implementation](https://github.com/googlecolab/colabtools/blob/main/google/colab/output/_js.py). Display and installation occur in the same cell. The installer waits briefly for that cell document to contain the unique widget class; it **never traverses parent/iframe documents**.

Unavoidable diagnostic assumptions are explicit:

- ipympl frontend 0.12 renders two canvases, with the interaction overlay second. This DOM ordering is not a stable public extension API. A different count stops installation; a matching count alone does not prove the hosted module version.
- Python accesses `_position_editor` and Configure's first child for the disposable controller. Neither is promised as a public extension interface.
- Synthetic mouse events must be accepted by the existing ipympl handlers; no private widget-manager/model-send interception is used.
- The adapter stores only its own cleanup/trace API on the scoped root. Browser trace download buttons use standard DOM/Blob APIs, local to that widget. No package writes or custom remote code loading.

If Colab isolates the widget from eval_js's output document, the notebook returns a framing failure and stops. Stage 5A's CSS delivery does **not** establish JavaScript reachability. No injection into a widget iframe/manager or selector-search workaround is provided. On inaccessible framing or rejected synthetic events, report the limitation rather than introducing an invasive fallback.

Scientific execute was replaced with a raising guard. No propagation occurred.

Notebook Python setup was also executed in both synthetic and beamplane modes with Colab output.eval_js mocked. Both passed; embedded adapter source equals the standalone file. Code cells compile and contain no saved outputs. Local environment is the retained Stage 4F Python 3.12 environment with ipympl 0.10.0. These tests do not join the browser and Python paths and do not qualify an iPad, native DOM dispatch, real mouse input or hosted frontend framing.

Expected trace for successful touch/pen: pointerdown → emitted mousedown → emitted mousemove(s) → emitted mouseup, with compatibility events suppressed if generated. Expected cancellation: pointerdown → mousedown → optional motion → cancel reason → mouseleave, **no mouseup**. These are locally tested expectations, not observed hosted sequences.

## Hosted qualification instructions and stop gates

1. Open the local notebook manually in a compatible Colab session. No publishing or installation is performed by this stage. Run synthetic mode. Retain preflight output and actual iPadOS/browser versions.
2. If the scoped root/overlay is not accessible in the same document, stop. Do not attempt another DOM or frame route.
3. Use browser trial labels and matching Python trial labels. Exercise finger, Pencil and physical mouse independently; mark unavailable devices untested. Download browser and Python JSON evidence before rerun/removal.
4. Verify complete event sequences, valid positions, scrolling outside, same-document cancellation and recovery. Test zoom, leave/release outside, second contact, interruption and rapid recontact. Inspect duplicate releases and stale motions.
5. Use **Remove adapter** before rerunning or switching mode, retaining both traces first. Then test the new disposable beamplane: Move center and Tilt endpoint for each active beam; check numeric edits and release synchronization. No Run.
6. Canceled gestures must preserve the draft request exactly. Completed remains absent in this diagnostic. Desktop mouse with adapter installed/removed must match baseline. If any gate fails, stop; do not broaden into a production adapter.

Browser trace is capped at 2,000 records with a dropped counter; Python trace is capped at 2,000 events. Keep trials short and start a new diagnostic after saving if the cap is reached. Missing events after the cap cannot be treated as browser evidence.

## Recommendation

The prototype shows a small adapter can express the required event semantics while reusing LCProp's controller. It does **not yet establish** a reliable, maintainable Colab extension boundary. Production remains NO-GO until real browser traces prove same-document access, synthetic dispatch, cancellation/deduplication, pixel mapping and desktop compatibility. A supported ipympl frontend extension/upstream integration would be preferable to permanent reliance on the two-canvas DOM order. If framing blocks this experiment, stop and scope that supported integration separately; a second graphical interface is not yet justified.
