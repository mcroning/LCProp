## Capability scope and resource handling

The frontend exposes reduced x-only and full x–y PR, each Static and TD, plus
separately named Unified Static and published optical-first reduced Static.
Route-appropriate controls, beam/screens, XY/XZ/YZ saved-result views, native
experiment/result codecs and CPU accepted-state continuation reuse the existing
engine. See [capability map](../../records/CAPABILITIES.md) and
[limits](../../records/LIMITS.md) for concrete boundaries.

CPU does not probe CUDA. Auto reviews a resolved backend before dispatch; explicit
GPU never silently falls back. Compatible but numerically unqualified GPU requests
require opt-in and a separately compatible runtime. This CPU opener installs no
CuPy and adds no numerical/GPU qualification. Runtime-aware estimates are warnings,
not measured peaks; explicit acknowledgement does not override native scientific
validation or genuine runtime/backend incompatibility. No scientific grid,
precision, physics or retention is silently changed. Stop remains cooperative.
