# Desktop → PR Colab capability map

Specification inspected: public main `8c6b4d069db4ea05f2922ba4da9c382cc3286218`, especially `src/lcprop/pr/gui/{request_adapter,evolution_panel,material_panel,beam_panel,grid_panel,main_window,transverse_continuation}.py`. This is a code capability comparison; the installed desktop was neither launched nor altered.

The standalone `frontend/pr_colab` overlay imports the unchanged ce915366 engine. It does not replace any `lcprop` module. Native dataclasses, numerical preflight, operations, experiment/result codecs and read-only products remain engine-owned. The existing notebook controller/beam/plot/file components and rc5 opening pattern are reused.

## What the preserved numerical evidence means

The original ce915366 qualification and failed attempts remain untouched. They support only their recorded requests, runtime stacks, metrics and tolerances. Local request mapping, mock dispatch and saved-file checks here establish frontend behavior, not arbitrary numerical validity or new GPU qualification. Edited compatible GPU requests are explicitly marked unqualified.

`ENGINE-VS-MAIN.json` compares the exact wheel against current public main: 260 identical non-notebook Python files and 9 differences already present in that preserved build (backend; LC bias/runtime/workflows/codecs; optical launch; transverse Static workflow/codec). This frontend did not create or reconcile those differences. The ce915366 wheel is not misrepresented as the rc5 wheel or the installed desktop binary.
